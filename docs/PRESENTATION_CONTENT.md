# Assembler — presentation content

## Slide 1 — Assembler

**From business intent to working voice agents**

Built on AssemblyAI.

Visual: creation screen. Footer: Independent hackathon project.

## Slide 2 — Problem

One voice agent. Too much manual setup.

Prompts · Data · Tools · APIs · Rules · Escalation · Outcomes

Businesses must connect all seven before a conversation can produce useful work.

## Slide 3 — Solution

Describe the workflow. Assemble the agent.

Write in normal language. Assembler assembles a Blueprint locally from curated configuration for review.

## Slide 4 — How It Works

Intent → Blueprint → Data / Tools / Rules → Generic Runtime → AssemblyAI → Business Action

Connections link approved actions to the business systems they need.

## Slide 5 — Product

Review the work before the first call.

- Dynamic fields capture the right information.
- Tools and connections define business actions.
- Rules and workflow guide decisions and escalation.

Visual: creation screen beside a real Blueprint Review. If generation is unavailable, use an existing saved blueprint and label it accurately.

## Slide 6 — Not Another Template Bot

Six starting points. One architecture.

Auto Repair · Ecommerce · Real Estate
Restaurant · IT Helpdesk · Property Management

Starters fill an editable description and select curated fields and actions. The same Voice Agent creation path and generic runtime handle each workflow.

## Slide 7 — AssemblyAI

AssemblyAI handles voice infrastructure.
Assembler handles the business workflow layer.

Voice Agent API + WebSocket: agent configuration and voice interaction.
Assembler builds the Blueprint locally before sending an agent configuration to the Voice Agent API.

Speaker note: external AssemblyAI endpoints could not be live-tested in this network. Local verification uses mocks; no successful live voice call is claimed.

## Slide 8 — Vision

**Any business workflow → a deployable voice agent**

From conversation to a useful business outcome.

Speaker note: this is the vision. Deployment requires working service connections; production authorization and tenant isolation are outside this hackathon implementation.
